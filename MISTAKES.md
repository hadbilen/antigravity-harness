  3. `_extract_shell_c_payloads` only unwrapped known shells and the literal `script` binary, never Python string argv literals, terminal multiplexers, or `-c` payloads of arbitrarily named binaries; `_prompt_controlling_tty` never flushed pending terminal input before prompting.

Non-global workspace discovery (`guard/environment.py`) previously registered whole `.gemini` directories, and `_custom_enforced_governance_roots` in `guard/agy_hooks.py` enforced raw `$HOME/.gemini` entries from `environments.json` verbatim, blocking writes to Antigravity's per-conversation runtime artifact/scratch tree (`~/.gemini/antigravity/brain`); `guard/doctor.py` also lacked warnings for deleted workspace roots or `$HOME`-rooted non-global entries.

### 2026-10-25: Non-Seekable `/dev/tty` `os.fdopen(..., "r+")` Rejection in `guard/approval.py` (`install.py` Controlling-Terminal Prompt Failure)
- **Date & Incident:** On `2026-10-25`, running `python3 install.py` interactively in Konsole over a write-protected `~/.gemini/config` printed the confirmation header (`[ANTIGRAVITY GUARD — HUMAN CONFIRMATION REQUIRED: install]`) and immediately exited with `[APPROVAL REQUIRED]` before printing `Type 'yes' to confirm: `; typing `yes` afterward executed GNU `yes` (`/usr/bin/yes`) in the parent `bash` shell.
- **Root Cause:** `_prompt_controlling_tty()` in `guard/approval.py` wrapped the POSIX `/dev/tty` file descriptor via `os.fdopen(fd, "r+", encoding="utf-8", errors="replace", buffering=1)`. In Python 3, buffered read-write mode (`"r+"`) constructs `io.BufferedRandom`, which requires `raw.seekable()` and immediately raises `io.UnsupportedOperation: File or stream is not seekable` (a subclass of `OSError`) on character devices; `tty_approver()` caught `OSError` silently and returned `False`, while unit tests mocked `builtins.input` or `sys.stdin` (`sys.stdin is not sys.__stdin__`) and never exercised `/dev/tty` on a real kernel pseudo-terminal.
- **Impact:** Human operators could not approve `python3 install.py` (or interactive `agy-guard` administration commands) in a real POSIX terminal when `~/.gemini/config` was already locked, and typing `yes` after premature exit launched `/usr/bin/yes` at the shell prompt.
- **Preventive Invariant:** `_prompt_controlling_tty()` in `guard/approval.py` performs seek-free raw descriptor `os.write` and bounded `os.read` directly on `/dev/tty` inside `try ... finally: os.close(fd)` without `io.BufferedRandom`, logs unexpected `OSError` failures via `approval.tty_error` instead of swallowing them silently, and is pinned end-to-end by `test_tty_approver_and_locked_reinstall_on_real_controlling_pty` in `tests/test_security_and_protocol_seams.py` using a real `TIOCSCTTY` controlling terminal subprocess.

### 2026-10-19: Antigravity 2.0 PreToolUse Required Decision Contract, Runtime Subdirectories & `_INSTALL_PY_RE` Argument False-Positive
- **Date & Incident:** Immediately after deploying `guard/agy_hooks.py` (`harness-gate`) via `install.py`, Antigravity 2.0 blocked benign `run_command` and file-write calls with `tool call denied by pre-tool hook: `, `_targets_governance_dir` treated runtime subdirectories inside `~/.gemini/config/` (`plugins/`, `sidecars/`) as locked governance seams, and `_INSTALL_PY_RE` blocked read-only commands such as `git diff v1.4.0 -- install.py` that mentioned `install.py` as a filename argument.
- **Root Cause:**
  1. `handle_pre_tool_use` applied Claude Code's `PreToolUse` pass-through convention (returning `{}` to defer to host permissions), whereas Antigravity 2.0's `PreToolUse` protojson contract (`agy-customizations/docs/hooks.md`) requires an explicit `"decision"` field (`"allow"`, `"ask"`, `"force_ask"`, `"deny"`) and fails closed as `"deny"` when `"decision"` is empty.
  2. `_targets_governance_dir` checked `is_within(expanded, ~/.gemini/config)` without exempting `ANTIGRAVITY_RUNTIME_ENTRIES` (`plugins`, `sidecars`, `projects`, `cache`) defined in `guard/environment.py`.
  3. `_INSTALL_PY_RE` used `(?:^|[;&|()\s])(?:python3?\s+|(?:\./|/)?[^\s;|&]*)install\.py\b`, where both `(?:\./|/)?` and `[^\s;|&]*` could match zero characters after whitespace, matching any command argument named `install.py`.
- **Impact:** Matched `PreToolUse` tool calls were rejected on pass-through, and read-only git/file inspection commands referencing `install.py` as a path argument were falsely blocked.
- **Preventive Invariant:**
  1. Native Antigravity 2.0 `PreToolUse` hooks must always emit an explicit `decision` (`{"decision": "allow"}` on pass-through, `"force_ask"` on destructive operations, `"deny"` on forbidden operations), whereas `PreInvocation` and `Stop` return `{}` on no-op.
  2. Governance path shields (`_targets_governance_dir` and `_command_mutates_governance`) must stay aligned with `ANTIGRAVITY_RUNTIME_ENTRIES` in `guard/environment.py` so plugin and sidecar directories remain operable (`tests/test_agy_hooks.py`).
  3. Command-blocking regexes in `PreToolUse` must anchor on command/interpreter invocation boundaries (start of command, shell operator `[;&|()]`, interpreter `python3?/sh/bash/env/exec`, or explicit path prefix `./` / `/`), never bare whitespace (`tests/test_agy_hooks.py`).
