# ADR-0014: Predictive Context-Window Handoff, `builtin/.checksum` Watchdog, `rust-harden` Greenfield Architecture, Structured Decision Provenance, and `procoder` Template Archival

**Date**: 2026-11-22
**Status**: accepted
**Amends**: [ADR-0005](0005-antigravity-v2-32-compatibility-and-hook-modernization.md) (partial: `builtin/.checksum` bundle drift monitoring), [ADR-0009](0009-cognitive-slimming-skill-consolidation-and-midturn-hook-silence.md) (partial: `21 -> 20` top-level skills reclaiming `680` bytes of frontmatter), [ADR-0011](0011-governance-templates-rust-harden-and-simplicity-auditor.md) (partial: `--greenfield` mode and 4th `rust-harden` progressive-disclosure playbook), [ADR-0012](0012-repostate-vulkan-template-low-friction-ux-and-rustify-patterns.md) (partial: `9 -> 8` tracked repositories, `rustify -> rust-harden` post-parity handoff, and opt-in `DECISIONS` / `procoder.SKILL` templates), [ADR-0013](0013-swarm-orchestrator-hook-isolation-modularity-and-guard-hardening.md) (partial: dynamic predictive context-window handoff advisory in `PreInvocation`)
**Deciders**: Human Operator (`tugay`), Antigravity Harness Maintainers
**Proposed By**: Model (Gemini 4 Neon, XHigh)
**Approved By**: User
**Authority**: Model Recommendation

## Context

Five operational gaps remained after `ADR-0013`: (1) long sessions lacked an empirical, low-token pre-compaction handoff warning grounded in post-`CHECKPOINT` active token usage and incoming job demand, forcing operators to either guess context fullness or accept unexpected mid-task compactions; (2) Antigravity updates to bundled plugins or sidecars under `~/.gemini/antigravity/builtin/plugins/swarm/` changed `builtin/.checksum` without modifying `builtin/skills/`, escaping `SessionStart` drift detection; (3) `rust-harden` covered existing Rust refactoring (`--internal` / `--contract`) while omitting day-1 greenfield crate/workspace architecture, and `rustify` lacked an explicit post-parity handoff to `rust-harden`; (4) `docs/adr/` and project records could not distinguish binding `User Constraint` mandates from `Model Recommendation` designs for `/retro` model calibration; and (5) `skills/procoder/SKILL.md` consumed `627` bytes of global YAML frontmatter and an active upstream repository slot on every unrelated workspace even though it applies only inside `.procoder/`-governed repositories. The decision-driving constraint is **delivering all five upgrades while reducing global top-level skills (`21 -> 20`, aggregate frontmatter `<= 10,200 / 10,800` B), avoiding hardcoded `%` context cutoffs, keeping `guard/agy_hooks.py <= 350` lines with `pre-invocation (inv=2)` cold-start median `< 100 ms`, preserving all `ADR-0001..0013` and `GEMINI.md` Rule 9/12/17 invariants, and retaining Apache-2.0 attribution**.

## Decision

We adopt five coordinated upgrades across hooks, upstream drift monitoring, Rust skills, decision governance, and opt-in templates:

1. **Dynamic Predictive Context-Window Handoff Advisory (`guard/hooks/pre_invocation.py`):** Evaluate strictly on fresh user turns (`invocationNum == 1`) for non-auxiliary roles (silenced on `inv > 1` fast path and for `monitor`, `narrator`, `verifier`, and `readOnly` roles). Tail-read a bounded slice of `transcriptPath` (widening `512 KiB -> 2 MiB` when no `PLANNER_RESPONSE` or `CHECKPOINT` is found) to locate the newest `type == "CHECKPOINT"` compaction reset, read the latest post-checkpoint `PLANNER_RESPONSE` active total (`input_tokens + cache_read_tokens`, plus `cache_creation_input_tokens` when present, without double-counting inclusive `prompt_tokens`), compute trailing median `burn_rate`, estimate incoming job demand from prompt weight, unchecked primary-workspace `tasks.md` items, and observed `burn_rate`, and compare headroom against empirical model-specific `model_compaction_ceilings` (seeded in `upstream_state.seed.json` with `guard/upstream.py` fallback and `MC-01` calibration) without any fixed `%` cutoff. Suppress trivial Tier-1 micro-edits and `1` small remaining `tasks.md` item when no heavy workflow signal is present; never hard-deny. Deliver Tier 1 (Yellow) via `0`-token `metadata.user_markdown` (`systemMessage: ""`, throttled by `REHINT_TURN_GAP`) and Tier 2 (Red) via a one-time per-conversation latched terse `<= 60`-token `systemMessage` (silencing subsequent Tier-1 and Tier-2 advisories for that conversation) instructing the model to offer a 1-sentence continue-vs-clean-`HANDOFF.md` choice before heavy edits.
2. **Antigravity `builtin/.checksum` Bundle Watchdog (`upstream_watcher.py`, `check_skills.sh`, `guard/upstream.py`, `upstream_state.seed.json`):** Monitor `~/.gemini/antigravity/builtin/.checksum` (`builtin_bundle_checksum`, rejecting symlinks, non-regular files, and malformed/control-character payloads with explicit tamper warnings while degrading cleanly when the default path is absent) alongside `builtin/skills` SHA-256 on `SessionStart` so bundled plugin/sidecar updates surface as first-seen `metadata.user_markdown` notices even when `builtin/skills/` is unchanged, and document measurable `MC-01` compaction-ceiling calibration (`N >= 3` non-manual checkpoints, `p10` rounded down to `10,000` tokens, `>= 25,000` or `>= 10%` shift) in `skills/upstream-auditor/references/model-calibration-matrix.md`.
3. **`rust-harden` Greenfield Architecture (`--greenfield`) and `rustify` Post-Parity Handoff:** Add `skills/rust-harden/references/greenfield-architecture.md` (`0` global frontmatter bytes, verified TOML blocks for workspace partitioning, Edition `2024` + MSRV + `[workspace.lints]` + `clippy.toml` with panic/indexing test exemptions + Cargo RFC 3923 `"3 days"` `.cargo/config.toml` publish-age cooldowns, `thiserror`/`anyhow` error seams, day-1 ownership/newtype/typestate APIs, and `#[expect(lint, reason = "...")]`), expose `--greenfield` in `skills/rust-harden/SKILL.md` (`507 <= 520` B frontmatter, preserving default `--internal`), calibrate greenfield Rust prompts in `guard/hooks/pre_invocation.py` while keeping bare `Cargo.toml`, routine `.rs`, Turkish non-creation prose, and `rustify` negative controls intact, and add a sequential post-parity handoff in `skills/rustify/SKILL.md` §1 preserving `context-and-artifacts.md` §1's `Anti-Mixing Sequencing Rule`.
4. **Structured Decision Provenance and Opt-In `DECISIONS.template.md`:** Add `Proposed By` (`User` | `Model (<Model Display Name & Effort>)`), `Approved By` (`User | pending`), and `Authority` (`User Constraint` | `Model Recommendation`) to `docs/adr/template.md` and `skills/harness/references/adr.md` with full backward compatibility for `docs/adr/0001..0013`. Ship strictly opt-in, bounded (`<= 150` lines; prune at `>= 135` lines / `>= 35` rows) `templates/DECISIONS.template.md` with a single-source-of-truth boundary vs. `docs/adr/`, register `"DECISIONS.md"` in `scripts/meta_audit.py` `KNOWN_EXTERNAL_MD`, integrate provenance inspection across `context-and-artifacts.md` and `skills/retro/SKILL.md`, and export `templates/DECISIONS.template.md` verbatim across all Porter emitters.
5. **Opt-In Archival of `procoder` (`21 -> 20` Top-Level Skills, `9 -> 8` Tracked Repos):** Archive `skills/procoder/SKILL.md` into opt-in project-local `templates/procoder.SKILL.template.md` (mirroring `templates/vulkan.SKILL.template.md`: copy to `.agents/skills/procoder/SKILL.md` inside `.procoder/` repositories while preserving Apache-2.0 attribution in `THIRD_PARTY_NOTICES.md` and `installers/packaging/PKGBUILD`) and remove `skills/procoder/` from top-level `skills/` (reducing aggregate frontmatter from `10,666` B to `9,986` B, reclaiming `680` B). Add `"procoder"` to `CONSOLIDATED_SKILL_SLUGS` in `guard/environment.py` so `install.py` and `agy-guard init` back up and prune stale `~/.gemini/config/skills/procoder` on upgrade and `porter.py import --as-skill procoder` blocks accidental global re-import; remove `"procoder"` from `SKILL_HINTS` and `_DISTINCTIVE_SKILL_SLUGS` (`guard/hooks/pre_invocation.py`), `MODE_SKILLS` (`scripts/meta_audit.py`), and `tracked_repositories` (`upstream_state.seed.json` & `guard/upstream.py`, with retired-entry pruning in `reconcile_state_with_seed`, `upstream_watcher.py`, and `check_skills.sh` preserving custom user repos).

## Alternatives Considered

### Alternative 1: Use a Fixed `%` Context Cutoff (for Example `70%`) and Inject a Permanent Reminder on Every Turn
- **Pros**: Simpler arithmetic in `pre_invocation.py` with no `tasks.md` or prompt-weight estimation.
- **Cons**: Fires false alarms on trivial Tier-1 edits or final-task completions, wastes model tokens on every turn once crossed, and ignores huge differences between small-ceiling (`180K`) and large-ceiling (`512K`) models or post-`CHECKPOINT` compaction resets.
- **Why not**: Rejected on token waste and false-positive noise; dynamic headroom vs. estimated job cost with `CHECKPOINT` reset, `0`-token Tier-1 `user_markdown`, and one-time Tier-2 latch avoids fixed-percentage misfires.

### Alternative 2: Keep `procoder` as a Global Top-Level Skill and Add a Separate `rust-greenfield` Top-Level Skill
- **Pros**: Zero migration needed for `.procoder/` users and dedicated top-level discoverability for greenfield Rust projects.
- **Cons**: Pushes top-level skills to `22` and pushes aggregate YAML frontmatter past `ADR-0009`'s `10,800`-byte ceiling, taxes every non-`.procoder/` session with `627` B of unused prompt metadata, and fragments Rust guidance across three overlapping top-level skills.
- **Why not**: Rejected on frontmatter budget and routing clarity; archiving `procoder` to `templates/procoder.SKILL.template.md` and placing greenfield Rust inside `skills/rust-harden/references/greenfield-architecture.md` drops global skills to `20` and aggregate frontmatter to `9,986` B (`<= 10,200` B).

### Alternative 3: Make `DECISIONS.md` Mandatory on Every Repository and Backfill `ADR-0001..0013`
- **Pros**: Uniform provenance headers across every historical ADR and automatic root ledger availability.
- **Cons**: Violates `GEMINI.md` Rule 4 (YAGNI) by creating unsolicited root files in user repositories, risks dual-ledger drift with `docs/adr/`, and rewrites historical ADR records with speculative provenance.
- **Why not**: Rejected on YAGNI and historical-integrity grounds; keeping `DECISIONS.template.md` strictly opt-in (`<= 150` lines, 1-line ADR pointers) and preserving `ADR-0001..0013` backward compatibility eliminates drift.

## Consequences

### Positive
- Operators receive dynamic, empirical pre-compaction context advisories at zero model-token cost for Tier 1 and at most one terse latched `systemMessage` for Tier 2, with zero `inv > 1` latency regression (`< 100 ms`).
- Bundled Antigravity plugin/sidecar updates (`builtin/.checksum`) surface immediately at `SessionStart` without modifying `~/.gemini/antigravity/builtin/` or adding per-turn overhead.
- Greenfield Rust architecture (`--greenfield`) and post-parity `rustify -> rust-harden` handoffs are covered at `0` net global frontmatter bytes while preserving every existing negative control.
- Future ADRs and opt-in `DECISIONS.md` ledgers capture `User Constraint` vs. `Model Recommendation` provenance for `/retro` model calibration without touching `ADR-0001..0013`.
- Global top-level skills shrink from `21` to `20`, aggregate YAML frontmatter drops from `10,666` B to `9,986` B (`-680` B), tracked external repositories drop from `9` to `8`, and upgrading installations automatically back up and prune stale `skills/procoder` directories and retired `"procoder"` upstream ledger entries.

### Negative
- Operators working in `.procoder/` repositories must copy `templates/procoder.SKILL.template.md` to project-local `.agents/skills/procoder/SKILL.md` once per repository instead of relying on a global `/procoder` skill.
- Empirical `model_compaction_ceilings` require periodic recalibration via `/audit-upstream --model` (`MC-01`) when new model families ship with different compaction ceilings.

### Risks
- **Unmapped or new model families using the conservative `200K` fallback ceiling:** Mitigated by `known_placeholder_models` resolution before ceiling lookup, conservative `default: 200000` behavior that only emits non-blocking advisories, and `/audit-upstream --model` `MC-01` recalibration.
- **Stale `skills/procoder` directories or `upstream_state.json` `"procoder"` entries surviving on upgraded hosts:** Mitigated by registering `"procoder"` in `CONSOLIDATED_SKILL_SLUGS` (`guard/environment.py`) for automatic backup-and-prune in `install.py` and `agy-guard init`, plus retired-repo pruning (`"procoder"` -> `"azrtydxb/procoder"`) in `guard/upstream.py`, `upstream_watcher.py`, and `check_skills.sh` covered by hermetic regression tests.
- **Apache-2.0 license notice loss after removing `skills/procoder/`:** Mitigated by keeping `templates/procoder.SKILL.template.md` explicitly licensed `Apache-2.0` with a modification notice, retaining the full `azrtydxb/procoder` Apache-2.0 license text in `THIRD_PARTY_NOTICES.md` and `installers/packaging/PKGBUILD`, and pinning both in `tests/test_adr0014_predictive_handoff_rust_decisions_procoder.py`.
