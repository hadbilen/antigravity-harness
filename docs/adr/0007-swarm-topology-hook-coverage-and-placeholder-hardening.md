# ADR-0007: Swarm Execution Role Alignment, PreToolUse Hook Coverage Expansion, Model Placeholder Gate, and Linked-Worktree Boundary Hardening

**Date**: 2026-11-15
**Status**: accepted
**Deciders**: Human Operator, Antigravity Harness Maintainers

## Context

An ecosystem alignment, adversarial boundary review (`AC-1..AC-8`, `W1..W4`), and subsequent runtime evaluation audit (`AC-9..AC-10`, `W5`, `2026-11-15`) identified six gap clusters spanning multi-agent skill instructions, `PreInvocation` / `PreToolUse` / `Stop` hook contracts, upstream model placeholder & future-flagship handling, and installer/worktree/test-boundary containment:

1. **Swarm & Role-Calibration Fragmentation (`AC-1`, `AC-5`):** Runtime support for isolated `native_swarm` (`workspace:"share"`), `orchestrator-*` models in `skills/upstream-auditor/upstream_state.seed.json` (`approved_customization_models`), and the 3-adapter dispatch model (`invoke_subagent`, `swarm`, `run_workflow`) lacked unified topology and role-calibration guidance across `skills/harness/SKILL.md`, `skills/marathon/SKILL.md`, `skills/unlazy/references/dispatch.md`, `skills/upstream-auditor/SKILL.md`, and `skills/upstream-auditor/references/model-calibration-matrix.md`. Separately, an architectural question (`AC-5`) remained on whether moving root `GEMINI.md` into `.gemini/` or slimming it further was needed to eliminate workspace/user-global double-injection while keeping the `<= 20,000`-byte ceiling enforced by `scripts/meta_audit.py`.
2. **Incomplete `PreToolUse` Delegation & Scheduling Gate (`AC-2`):** Native Antigravity multi-agent and timer tools (`post_message`, `send_message`, `define_subagent`, `schedule`) were absent from `PRE_TOOL_USE_MATCHER_TOOLS` in `guard/agy_hooks.py` and the matching `hooks.json` `PreToolUse` matcher regex. An agent could route customization/governance edits through swarm board mentions (`@all` or tracked workers), direct `send_message`, custom subagent definitions, or `schedule` triggers, or mutate `swarm_workers.json` non-transactional state across `run_workflow` steps.
3. **Host `MODEL_PLACEHOLDER_*` Opaque Diagnostics (`AC-3`):** When host state (`antigravity_state.pbtxt`) or hook payloads exposed `MODEL_PLACEHOLDER_M417` (or other `MODEL_PLACEHOLDER_*` identifiers) without concrete `<USER_SETTINGS_CHANGE>` transcript overrides or paired effort metadata, `skills/upstream-auditor/scripts/upstream_watcher.py` and `guard/agy_hooks.py` lacked canonical placeholder classification (`is_placeholder_model` / `_is_model_placeholder`) and seed-aware diagnostic guidance (`_resolve_placeholder_diagnostic` / `_seed_placeholder_diagnostic`), risking stale placeholder persistence in `upstream_state.json` or blind pass-throughs.
4. **Linked-Worktree & `Stop` Commit-History Attribution Gaps (`AC-4`):** Isolated swarm/subagent `git worktree` checkouts store `.git` as a file pointer rather than a root directory, bypassing naive `.git`-directory baseline discovery in `guard/test_boundary.py`. Meanwhile, `handle_stop` in `guard/agy_hooks.py` needed session-flight `base_head` tracking (`_session_flight_base_head`) across clean commits and linked worktrees so committed changes or explicit diffs do not slip past `TestBoundaryGuard` or leave stale stop strikes.
5. **Installer / Doctor Symlink Containment Gaps (`AC-4`):** `install.py` and `guard/doctor.py` lacked lexical path containment checks (`_is_within_lexically`) and `.agents/skills` / `plugins/` symlink boundary diagnostics (`_harness_skill_names`, `_check_plugins_symlinks`), leaving skill-directory symlink aliases underchecked.
6. **Runtime Hook Schema Drift, Intra-Turn Latency & Seam Hardening (`AC-9`, `AC-10` — `W5` Evaluation Report):** Live host payload analysis and evaluation findings (`E-01..E-09`) surfaced: (a) `handle_stop` whitelisting only `"NO_TOOL_CALL"` instead of blacklisting abnormal stops (`_NON_NORMAL_STOP_REASONS`), missing `"model_stop"` / `"TERMINAL_STEP_TYPE"` / `"INJECTED_RESPONSE"`; (b) `_extract_latest_user_prompt` reading `transcriptPath` before checking top-level `lastUserInput` / `last_user_input`; (c) redundant intra-turn (`invocationNum > 1`) `PreInvocation` scans and eager regex compilation on non-Pass-7 tables; (d) unprotected top-level `~/.gemini/{GEMINI,AGENTS}.md` overrides and silent `.agents/hooks.json` collisions; (e) missing `Bash Guard` `force_ask` prompts on out-of-workspace `rm -rf`/`mv`, DB drops, `find -delete`, `git branch -D` / `stash drop`, `docker ... prune -af`, and `chmod -R 777`; (f) over-broad Rule 17 blocking on non-harness `DESIGN.md` files and hard `deny` (instead of `force_ask`) on unrecognized future flagships with verified high effort; (g) missing `flight_recorder.json` baselines before mutating shell commands (`sed -i`) and undetected in-place assertion operator/matcher relaxation (`==` -> `>=`, `is not None`, `toBeTruthy`); (h) a repo-checkout path false positive in `_command_mutates_governance`; and (i) verbose `skills/*/SKILL.md` YAML descriptions plus undocumented cross-model-family verification and plain-language **Operator Summary (`Operatör Özeti`)** conventions.

## Decision

We adopt six coordinated hardening changes across Windows 1–5 (`W1..W5`, `AC-1..AC-10`):

1. **Unified Swarm Topology, Role Calibration & Root `GEMINI.md` Decision (`AC-1`, `AC-5`):**
   - Standardize **Swarm Execution Topology & Role Alignment** (`skills/harness/SKILL.md` §5.F, including concrete `monitor` defaults: `DurationSeconds >= 60`, `IsDaemon: false`, max `3` stall nudges, and `0`-conflict `git merge` verification before `swarm{action:"kill"}`), the **Swarm (`native_swarm`) vs. Single-Window (`unlazy`) vs. Multi-Window (`marathon`)** decision matrix and **Runtime Role & Rule 17 Calibration** table (`skills/marathon/SKILL.md`), the 3-adapter dispatch specification (`skills/unlazy/references/dispatch.md`), and role-aware `Target Role` calibration plus the explicit `(model_suffix, effort)` policy matrix (`skills/upstream-auditor/SKILL.md` and `skills/upstream-auditor/references/model-calibration-matrix.md`).
   - Lock the `W1` `deep-grill` architectural decision (`AC-5`) to **retain `GEMINI.md` at repository root** at its compacted `17,920`-byte footprint (well within the `<= 20,000`-byte UTF-8 ceiling verified by `scripts/meta_audit.py`), avoiding symlinks or hidden moves that would break Antigravity's root workspace rule discovery.
2. **Expanded `PreToolUse` Matcher & Fail-Closed Swarm/Workflow Ledger (`AC-2`):**
   - Extend `PRE_TOOL_USE_MATCHER_TOOLS` in `guard/agy_hooks.py` and `hooks.json` with `post_message`, `send_message`, `define_subagent`, and `schedule` (with authorized `expected_tools` expansion in `tests/test_guard_hardening.py` under `GEMINI.md` Rule 9 `## Authorized Test Modifications`).
   - Implement `_handle_post_message_pre_tool_use`, `_handle_send_message_pre_tool_use`, `_handle_define_subagent_pre_tool_use`, `_handle_schedule_pre_tool_use` (checking `IsDaemon`/`isDaemon`/`is_daemon` strict boolean validation and `Prompt` + `CronExpression` customization text), `_persist_post_message_cust_mentions`, `_transcript_subagent_is_downgraded`, `_worker_matches_downgraded` (including sharded `fork:` prefix matching and downgrade propagation), and fail-closed `swarm_workers.json` handling (`_swarm_ledger_context` and `_batch_update_swarm_workers_ledger` with `quarantine=False` single-lock batch persistence across multi-mention `post_message` and `run_workflow` `_pendingSwarmOps` flushes).
3. **Canonical `MODEL_PLACEHOLDER_*` Classification & Seed Diagnostics (`AC-3`):**
   - Treat `MODEL_PLACEHOLDER_*` labels consistently via `_is_model_placeholder` / `_seed_placeholder_diagnostic` in `guard/agy_hooks.py` (`_evaluate_customization_model_and_effort`, escalating unresolved placeholders to `force_ask` while honoring the latest in-session `<USER_SETTINGS_CHANGE>` transcript directive and verified effort) and `is_placeholder_model` / `_clean_concrete_model` / `get_pbtxt_model(include_placeholder=...)` / `_resolve_placeholder_diagnostic` in `skills/upstream-auditor/scripts/upstream_watcher.py` and `guard/upstream.py` so `cmd_status` and `cmd_ack` keep `last_audited_model` concrete while recording `last_pbtxt_model` placeholder transitions cleanly.
4. **Linked-Worktree `TestBoundaryGuard` & Session-Flight `Stop` Accounting (`AC-4`):**
   - Add `resolve_linked_worktree_root` in `guard/test_boundary.py` using `git rev-parse --git-dir --git-common-dir` to map linked worktrees (both standard `.git` and bare repositories with `worktrees/`) back to their canonical repository trust boundary while rejecting git submodules (`modules` in `git-dir`), and add `_session_flight_base_head` (handling both ancestor and amended non-ancestor `base_head` commits), `_has_linked_git_file` per-worktree stash ref fallback, `_prune_missing_flight_workspaces` dead-worktree cleanup, and multi-workspace `_collect_workspace_diff_status_ex` checks in `guard/agy_hooks.py`.
5. **Installer & Doctor Symlink Containment (`AC-4`):**
   - Harden `install.py` with `_harness_skill_names`, `".."` path-segment rejection, reverse `"skills"` index scanning, `_is_within_lexically` symlink containment checks during MCP config migration (`migrate_mcp_config`), regular-file collision backups in `install_governance`, and `chmod` `OSError` warnings in `ensure_skill_script_permissions`; extend `guard/doctor.py` (`diagnose`) with `_check_plugins_symlinks` (`os.walk(..., onerror=...)`) classifying dangling vs external/resolved symlink entries under `plugins/` and `.agents/skills/`.
6. **Evaluation Report (`2026-11-15`) Runtime Contract, Seam & Prompt-Budget Hardening (`AC-9`, `AC-10` — `W5`):**
   - Switch `handle_stop` in `guard/agy_hooks.py` to case-insensitive `_NON_NORMAL_STOP_REASONS` blacklisting (preserving `"in_flight"` state on abnormal stops while executing `Stop` gates on `"NO_TOOL_CALL"`, `"model_stop"`, `"TERMINAL_STEP_TYPE"`, and `"INJECTED_RESPONSE"`), prioritize `lastUserInput` / `last_user_input` in `_extract_latest_user_prompt`, add opt-in sanitized fixture capture (`AGY_RECORD_HOST_FIXTURES=1`) in `dispatch_hook`, and ship hermetic host contract fixtures under `tests/fixtures/host/` (`E-01`, `E-02`).
   - Fast-path intra-turn `invocationNum > 1` calls in both `skills/upstream-auditor/scripts/upstream_watcher.py` and `guard/agy_hooks.py` (`handle_pre_invocation`), and wrap non-Pass-7 module regex tables in `_LazyRegex` while keeping `SKILL_HINTS` and `ECOSYSTEM_ROUTING_HINTS` as compiled `re.Pattern` objects (`E-03`).
   - Add `~/.gemini/GEMINI.md` and `~/.gemini/AGENTS.md` to `_governance_roots()`, `_normalize_governance_globs()`, and `_command_mutates_governance()` (`deny`), anchor `antigravity-(?:harness|guard)` path detection to `.local/(?:state|share)/` and `/usr/(?:lib|share)/` (`E-09`), require `force_ask` on workspace `.agents/hooks.json` writes/mutations, and emit `[WARN]` diagnostics in `guard/doctor.py` (`E-04`).
   - Expand `Bash Guard` (`_DESTRUCTIVE_CMD_PATTERNS` + `_detect_out_of_workspace_rm_or_mv`) for out-of-workspace `rm -rf`/`mv`, DB drops (`dropdb`, `DROP TABLE|DATABASE|SCHEMA`, `TRUNCATE TABLE`, unconditional `DELETE FROM`), `find -delete`/`-exec rm`, `git branch -D` / `stash drop|clear`, `docker/podman ... prune -af`/`--volumes`, and `chmod -R 777` (`E-05`); scope `DESIGN.md` Rule 17 gating strictly to harness/customization scopes (`_HARNESS_SOURCE_FILES`, `.agents/DESIGN.md`, `~/.gemini/config/DESIGN.md`) and escalate unrecognized future flagships with verified `high`/`xhigh`/`max` effort to `force_ask` (`E-06`).
   - Record `_record_flight_pre_write` baselines on allowed mutating `COMMAND_TOOL_NAMES` calls (`sed -i`, `git commit`, etc.), detect in-place assertion operator/matcher relaxation in both `inspect_git_diff` (`guard/agy_hooks.py`) and AST-based `TestBoundaryGuard.python_weakening` (`guard/test_boundary.py`) (`E-08`), compact `skills/*/SKILL.md` YAML `description` fields by `27%` (`20,433` -> `14,855` chars) with zero Pass-7 loss, and codify cross-model-family verification (`Claude Opus 5.5 (High)` vs `Gemini 4`) plus plain-language **Operator Summary (`Operatör Özeti`)** rules in `skills/harness/SKILL.md` and `skills/audit/SKILL.md` (`E-07`).

## Alternatives Considered

### Alternative 1: Relocate Root `GEMINI.md` into `.gemini/GEMINI.md` or Replace with a Symlink to Eliminate Double-Injection
- **Pros**: Eliminates host loading of both user-global `~/.gemini/config/GEMINI.md` and workspace `GEMINI.md` when working inside the `antigravity-harness` repo itself.
- **Cons**: Breaks direct workspace-root constitutional enforcement inside `antigravity-harness` and relies on fragile hidden paths or symlink resolution behavior flagged by symlink safety checks.
- **Why not**: Rejected during `W1` `deep-grill` (`AC-5`). Maintaining the canonical copy at `GEMINI.md` (`17,920` bytes <= `20,000` limit) keeps constitutional invariants explicit, reviewable, and portable across clone workflows.

### Alternative 2: Restrict `run_workflow` Directly via Regex Blocklist Instead of `_swarmOverlay` / `_pendingSwarmOps` Dry-Check Replay
- **Pros**: Simpler `PreToolUse` implementation without maintaining an in-memory workflow overlay or deferred ledger operations.
- **Cons**: Either allows multi-step workflows to spawn a downgraded worker and then post customization work to it in the next call, or mutates `swarm_workers.json` on disk even when a subsequent workflow statement triggers `deny`.
- **Why not**: AST-level `_swarmOverlay` dry simulation with conditional commit (`L9201-9214`) guarantees both multi-step downgrade detection and atomic rejection on `deny`.

### Alternative 3: Silently Accept `MODEL_PLACEHOLDER_M417` as Equivalent to the Top Approved Model
- **Pros**: Zero `force_ask` interruptions when upstream host builds change internal placeholder IDs without updating `pbtxt` display labels.
- **Cons**: Violates fail-closed `Rule 17` governance: an unknown or downgraded host model behind a new placeholder ID could silently modify `skills/`, `agents/`, or `guard/`.
- **Why not**: Resolving concrete `<USER_SETTINGS_CHANGE>` transcript overrides first, falling back to `"force_ask"` with seed diagnostics when unresolved, and isolating placeholder IDs out of `upstream_state.json` preserves both usability and fail-closed verification.

## Consequences

### Positive
- Complete `PreToolUse` parity across all Antigravity 2.x agent delegation, messaging, subagent definition, and scheduling primitives (`post_message`, `send_message`, `define_subagent`, `schedule`, `swarm`, `invoke_subagent`, `run_workflow`).
- Linked `git worktree` swarm workers no longer evade `TestBoundaryGuard` or `handle_stop` diff attribution after intermediate commits.
- Upstream watcher state (`upstream_state.json`) keeps `last_audited_model` free of `MODEL_PLACEHOLDER_*` corruption while tracking `last_pbtxt_model` placeholder transitions and surfacing actionable seed diagnostics.
- Additive regression suites (`tests/test_w2_ac2_ac4_hardening.py`, `28` hermetic tests; `tests/test_w5_evaluation_remediation.py`, `9` hermetic tests + `tests/fixtures/host/`; `650` total tests) directly exercise `AC-2..AC-4`, `W3..W4` auditor-verified invariants, and `W5` (`AC-9..AC-10`) Evaluation Report runtime contract, security-seam, latency, and assertion-relaxation gates.

### Negative
- Expanding `PRE_TOOL_USE_MATCHER_TOOLS` increases `guard/agy_hooks.py` invocation frequency slightly whenever agents schedule timers, define subagents, or post swarm messages (mitigated in `W5` by `_LazyRegex` deferred compilation and intra-turn `PreInvocation` fast-paths).
- Unresolved `MODEL_PLACEHOLDER_*` host sessions without an explicit `<USER_SETTINGS_CHANGE>` transcript marker, as well as unrecognized future flagship models at verified high effort, will prompt humans via `"force_ask"` when touching governance or customization paths.

### Risks & Verification Resolution
- All 7 independent Tier-3 / Critical Exception auditors (`meta-auditor`, `contract-change-auditor`, `security-boundary-verifier`, `silent-failure-hunter`, `test-adequacy-auditor`, `consistency-auditor`, `specification-gap-auditor`) executed in `Window 3/4` followed by Mutual Falsification (`F-01`..`F-13`), complete closure of all remaining non-refuted `MEDIUM` and `LOW` findings in `Window 4/4` (`R-01`..`R-09`, `AC-8`), and full remediation of the `2026-11-15` Evaluation Report in `Window 5/5` (`E-01`..`E-10`, `AC-9..AC-10`). All confirmed findings (`0` unresolved `CRITICAL`/`HIGH`/`MEDIUM`/`LOW` findings) are resolved and pinned by `37` additive regression tests across `tests/test_w2_ac2_ac4_hardening.py` (`28`) and `tests/test_w5_evaluation_remediation.py` (`9`; `650` total tests).
